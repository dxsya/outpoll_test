# Тестовое задание: Dashboard торгового оборота предсказательных рынков

## Обзор

Необходимо разработать веб-приложение, которое визуализирует исторический торговый оборот двух крупнейших предсказательных рынков — Kalshi и Polymarket — с возможностью фильтрации по категориям.

Демо должно запускаться на localhost.

## Требования

### 1. Источники данных

- Платформы: Kalshi и Polymarket
- Кандидат самостоятельно находит подходящие источники данных (публичные API, открытые датасеты и т.д.)
- Использование реальных данных обязательно — моковые и статичные данные не принимаются
- Запросы к источникам идут с фронтенда: кэширование, дедупликация и отмена неактуальных запросов на стороне клиента

### 2. Основной график

- Отображать торговый оборот (volume) по времени для обеих платформ на одном графике
- Тип графика на усмотрение кандидата
- Оси: дата по X, объём торгов (USD) по Y, читаемое форматирование чисел и дат
- Легенда с цветовым разделением платформ, клик по легенде переключает серию
- Поддержка временных диапазонов: 7д / 30д / 90д / всё время
- Интерактив: hover-tooltip со значениями обеих платформ на одну дату, crosshair, выделение ближайшей точки
- Плавные переходы при смене диапазона и фильтров

### 3. Фильтрация по категориям

- Реализовать возможность включения/отключения категорий рынков при просмотре графика
- Кандидат самостоятельно определяет категории, исходя из доступных данных
- Фильтры должны влиять на отображаемый торговый оборот
- При снятии всех категорий — показывать понятное сообщение
- Выбранные фильтры и диапазон синхронизированы с URL, кнопки «назад/вперёд» работают ожидаемо

### 4. UI/UX

- Адаптивный интерфейс от 360px, на тач-устройствах tooltip работает по тапу и драгу
- Чистый, читаемый дизайн
- Загрузочные состояния (скелетоны в форме будущего контента) и обработка ошибок с возможностью повтора
- Пустое состояние и состояние «нет данных за период» различимы
- При смене диапазона старый график не схлопывается в пустоту, пока грузится новый
- Клавиатурная навигация, видимый focus, осмысленные aria-атрибуты

### 5. Производительность

- Переключение фильтров и диапазонов без заметных фризов
- Большое количество точек на длинных диапазонах обрабатывается через агрегацию или downsampling
- Пересчёты не выполняются на каждый рендер

## Технический стек

Ограничений нет — кандидат выбирает стек самостоятельно. TypeScript обязателен. Чартовую библиотеку использовать можно, но tooltip, crosshair, оси и поведение на мобильных должны быть доведены руками; собственная реализация графика на SVG или Canvas — плюс.

## Дополнительные фичи

Чем больше — тем лучше. Кандидату предлагается проявить инициативу: добавить собственные фичи и объяснить, почему они уместны и какую ценность несут для продукта. Примеры для вдохновения:

- 📊 Сравнение рыночных долей (pie chart / доля по категориям)
- 🔍 Поиск по конкретному рынку/событию
- 📈 Процентное изменение объёма (delta)
- 🌙 Dark mode с учётом системной темы
- 💾 Экспорт данных в CSV и графика в PNG/SVG
- 🔔 Выделение аномальных пиков объёма
- ⚡ Realtime обновление (polling или WebSocket)
- ⌨️ Горячие клавиши и command palette

## Главное

Самое важное — сдать работающий продукт и уметь объяснить каждое решение: откуда берутся данные, как считаются значения на графике, что означают цифры, где живёт состояние и что произойдёт при десятикратном росте объёма данных. Кандидат должен полностью понимать всё, что разработал.
